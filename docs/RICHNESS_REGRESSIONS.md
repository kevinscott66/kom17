# Richness regressions: monolith → strangler split

Surfaces where the legacy monolith (root `bot.py`)
showed MORE information / richer cards / extra sub-features than the new
`src/telegram_invite_bot/` pipeline — content trimmed or dropped during the
split (NOT correctness bugs; those were audited separately). Found by a read-only
audit in six passes (RR-1..RR-6), 2026-06-18.

Effort: **S** small (re-wire / add lines, keys often already exist) · **M**
medium (new query/keyboard) · **L** large (rebuild a panel/menu/sub-feature).
"keys exist" = the i18n strings are still in `i18n/data/*.yaml`, just no
longer rendered → cheap restore.

Status legend: ☐ open · ◐ partly restored (the note says which half) · ☑ done.

**All 75 items are ☑ as of 2026-08-08.** Where an item is closed by a
deliberate *non*-restoration (a legacy lever wired to nothing here, a data
source only the legacy process writes), its note says which part was
restored, which was excluded, and why — see #2, #73 and #74.
